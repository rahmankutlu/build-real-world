# Security policy

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability. Use the repository’s **Security → Report a vulnerability** form to send a private advisory with the affected revision, reproduction, impact, and any suggested mitigation.

We will acknowledge a report within five business days, keep the reporter informed, and coordinate disclosure after a fix is available. Do not access other people's data, degrade services, or use social engineering.

The architecture material is educational and is not a security certification. Please report unsafe examples—especially authorization bypasses, secret exposure, SSRF, webhook verification, upload handling, tenant isolation, or payment-data guidance—as documentation security issues.
